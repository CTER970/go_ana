## 第 14 轮 · 增强轮（S2.5 性能维度）· 2026-08-21（R13 移交项落地 + W20）

- **基线核查**：交接文档（docs/会话交接总结.md）实跑复核——pytest 198+2 外部
  / 仿真 19/19 / 对抗 144 全一致；V6 并行开发区 mtime 停在 08-20 09:15，
  超 24h 无外部写入，无并发风险
- **S2.5 性能维度深挖（交接候选 ①）**——`_update_review_state` 批量回流 O(n²)：
  - **实测坐实**（bench_review.py，300 手×15 候选合成树）：单次全量刷新
    15ms，整盘批量回流 = 300 次全量 = **4.8s UI 线程阻塞**；且 `_render_profile`
    每次刷新调 `get_recent_profile_summaries` → `_load_index()` **读盘+全索引
    解析**，入库棋局批量分析 = 300 次磁盘读
  - **根因两层**：① 一次刷新内 `evaluate()` 全主线重算被
    meaningful_problems/coverage×2/rating×2/commentary 等重复走 7-9 次
    （每次含 moveInfos 重排序）；② 批量分支每个节点回流都跑全量管线
    （评分/画像/解说也逐手重建，超出验收范围）
  - **修复 1（缓存收口）**：review.py 新增 `CachedReviewReport` 快照子类——
    实例级缓存 mainline/_move_infos(排序)/_eval(身份守卫)。**基类保持
    活读语义不动**：中途曾把缓存放基类，test_review #24-1（原地 pop
    prior 后同实例重读必须生效）当场拦截——契约测试咬住了错误方向，
    改为生产管线（_update_review_state）专用快照子类，两全
  - **修复 2（轻量档拆分）**：`_update_review_state(light=True)`——批量回流
    逐节点只做验收要求的实时部分（曲线/失误榜/当前手 loss/覆盖进度），
    评分/画像/解说推迟到完成时的全量补刷；`_render_review(light=True)`
    跳过解说重建。非批量单结果/导航/切谱仍走全量
  - **修复后实测**：单次全量 15→4.5ms（3.3×），整盘批量 **4.8s→0.9s
    （5.3×）**+ 消除 300 次读盘与逐手 Text/Treeview 重建（未计入基准，
    实际收益更大）。单回流计算 3.2ms < 一帧
  - **静态调用收口**：`ReviewReport._move_infos` 两处静态调用
    （app.py 候选推送/训练最佳手）改走新静态助手 `_sorted_move_infos`
- **移交项跟进（交接候选 ③）**：V6 并行会话仍无活动（mtime 未变），
  三项移交（test_ui_v6 缺 fixture / render.py+timeline.py PhotoImage 无
  master / test_coach_ui 自建销 root）维持等其自行处理
- **新增场景（仿真 19→20）**：W20 曲线×导航双向联动端到端——点曲线第 2 手
  → 棋盘跳转 + 光标竖线跟随（x 断言精确到 34.0/528.0）；点当前手无操作；
  棋盘回根 → 光标反向跟随；点目独占下点击被拦截（节点不动）。首跑即绿
  （联动链 navigated 事件总线 → _update_review_state → _refresh_graph 健康）
- **验证**：pytest 全量 198 绿 + 2 外部错误 ✅；仿真 **20/20** ✅；
  对抗 144 ✅；pyflakes 改动文件 0；自审查 21 OK / 0 P0 / 0 P1 / 1 P2
  （P2 为既有备忘 _mirror_mastery_to_events，非本轮引入）
- **资产新增**：`analyzer/bench_review.py`——复盘管线性能基准（合成树
  A/B 实测），性能维度后续轮可直接复跑
- **P3 备忘（下轮候选）**：跨刷新的增量评价缓存（当前每次刷新仍全量
