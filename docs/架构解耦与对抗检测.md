# 架构解耦与对抗检测体系（v4）

> 触发背景：用户要求"功能间解耦合、不冲突、显示不互相占用、退出逻辑合理"，并提出"对抗训练形式不断检测"。
> 根因诊断：8500 行单体 GoAnalyzer 类有 25+ 模式标志、11 叠加图层、17 散落退出函数、3 份不一致清理清单——
> 不是"再修几个 bug"能解决的，需要架构层解耦 + 持续对抗检测。
>
> 本轮交付：三个枢纽重构（图层注册表/事件总线/模式管理器/统一清理）+ 对抗检测体系（144 序列全枚举 × 14 不变式）+ red-team 补盲点修复 3 个真实缺陷。

## 第一部分：枢纽重构（解耦的三个根基）

### 步骤 1：图层注册表 + z-order（解决"显示占用冲突"）
- **问题**：redraw 是 100 行串联 11 个 _draw_*，互斥条件散落 14 个 if，每加图层要记得加 not scoring_mode
- **方案**：`_init_overlay_layers` 注册表，每个图层 `(z_order, name, condition_fn, draw_fn)`；redraw 保留背景层+棋子层硬编码，之后按 z_order 遍历注册表
- **效果**：新增图层零改 redraw，互斥语义集中管理
- **位置**：app.py `_init_overlay_layers` + `_layer_*_cond/draw` + `redraw`

### 步骤 2：事件总线（解决"刷新入口太重、各域强耦合"）
- **问题**：`_after_navigate` 是 26 处调用的全局扇出枢纽，已有调用方为性能"刻意绕开"它
- **方案**：`_init_event_bus` + `_subscribe(event, fn)` + `_emit(event)`；`_after_navigate` 改为临时态清理 + redraw + `_emit("navigated")`
- **效果**：各域独立订阅，重活可声明 defer（未来扩展）；26 个调用点不变
- **位置**：app.py `_init_event_bus` / `_subscribe` / `_emit` / `_on_navigated_*` + `_after_navigate`

### 步骤 3：模式管理器（解决"守卫散落、互斥靠手写 if"）
- **问题**：5 个守卫散落，do_goto_root 等处复制粘贴守卫逻辑
- **方案**：`active_modes() -> set` + `can(action) -> bool` 统一查询接口
- **效果**：新增功能只需在 active_modes 注册，守卫自动一致；I13 不变式统一验证互斥
- **位置**：app.py `active_modes` / `can` / `_block_training_turn_silent`

### 步骤 4：统一换棋谱清理（解决"三份不一致清理清单"）
- **问题**：`_load_project_from_path`/`do_import_sgf`/`do_reset` 三份手动清理清单不一致
- **方案**：`_reset_for_new_game()` 封装所有"换棋谱时的状态重置"，三个入口共用
- **效果**：新增清理项只改一处；do_reset 不再 _block_in_scoring 拦截（清空本就该退出点目）
- **位置**：app.py `_reset_for_new_game` + 三个入口调用

## 第二部分：对抗检测体系（安全网 + 持续验证）

### 步骤 5-8：确定性全枚举检测器
- **`adversarial_harness.py`**：无头实例化（GoAnalyzer + _auto_start_attempted=True + mock弹窗 + update_idletasks）+ clean + seed_fixture + pump_after_callbacks
- **`invariants.py`**：14 条状态不变式（互斥/换棋谱/Canvas图层/导航拦截/窗口生命周期）
- **`actions.py`**：12 个动作原子（play/takeback/redo/reset/pass/enter_scoring/exit_scoring/toggle_pv/open_drill/close_drill/toggle_situation/switch_game）
- **`test_adversarial.py`**：pairwise 全枚举 12×12=144 序列，每步按动作 category 查对应不变式组

**检测结果**：144 序列 × 14 不变式 = **0 处违规**。检测器敏感性已验证（能抓真违规，不报假阳性）。

### 步骤 9：red-team 补盲点（修复 3 个真实缺陷）

red-team agent 通读源码，找出 6 个现有不变式没覆盖的盲点，其中 3 个是真实 bug 已修复：

| 盲点 | 严重度 | 问题 | 修复 |
|---|---|---|---|
| **B1** | 高·泄题 | drill/复习时 toggle_pv 无守卫，主变序号画棋盘=公布答案 | toggle_pv 加盲测守卫 + 固化 I8 不变式 |
| **B3** | 中·守卫缺口 | enter_scoring 漏查 mistake_review（另三个入口都查了） | enter_scoring 补 mistake_review 守卫 + 固化 I13 统一互斥 |
| **B4** | 中·nid残留 | do_reset 不走统一清理，_double_pass_prompted/_scoring_suggestion_prompted 残留 | do_reset 改用 _reset_for_new_game + 固化 I14 nid缓存归零 |

新增不变式：I8（盲测防泄题）、I13（统一互斥 active_modes≤1）、I14（nid缓存归零）。

未修的盲点（B2 候选/分支叠加、B5 窗口stale、B6 scoring期间ownership）列为后续改进。
