应用从"工具工作台"升级为"围绕棋手学习过程组织"的五页面结构：

```

├── 今日学习（左栏第一项，按需点击；不默认占屏）：继续复盘 / 今日复习 / 当前训练主题 / 最近趋势
```

- 首页只读既有数据（棋谱库/错题本/学习事件/画像缓存），不触发任何重新分析；空态按 V6 §69 全覆盖；构造懒加载，首次进入才读数据。
- 响应式（V6 §22/§72 实装）：窗口变窄先收左导航（176→64→56，收起用单字短标签），棋盘永远最后被压缩；复盘页显示/分栏恢复/页面切换都会重算棋盘自适应尺寸，复盘页未显示时按断点估算，杜绝棋盘卡在默认尺寸被裁切。
- 学习/研究分段：学习模式隐藏候选叠加与 AI 首选提示并记忆原状态，研究模式恢复；当前默认研究（Phase 5 复盘页学习化完成后翻转为学习默认）。
- 回归：`test_ui_v6.py` 三层验证（Token：ui/ 内无散落色值；Structure：五页注册+路由+旧工作台嵌入；State：模式互斥+首页稳定刷新）。

V6 已实施进度：Phase 1-4 + 6 完成（设计系统 / Shell / 首页 / **棋谱页内嵌**（Toplevel→一级页面，只换容器：复用原搜索/扫描/双击打开/画像身份全部逻辑，内嵌模式"关闭"=返回复盘页且页面复用） / **学习时间轴**）。

**学习时间轴（`ui/timeline.py`，V6 §38-43 的标志性视觉语言）**：传输区常驻条——颜色=目损档（<1 目无标记 / 1-3 黄 / 3-6 橙 / >6 红），**紫色外圈=学习价值**（本盘学习节点，learning_priority 专用紫，两概念绝不共用一种颜色）；点击跳转任意一手，悬停显示"第N手 · 损失X目 · 重点学习"（不暴露内部算法数字）；数据随复盘状态更新，优先级来自 LearningEvent。

## 一、产品定位与设计原则

本项目是**基于个人历史实战的围棋学习系统**，不是通用 KataGo 驾驶舱。所有界面决策用这四条原则裁决：

1. **学习优先**：普通用户的日常动线是「导入棋谱 → 复盘重下 → 间隔复习 → 看学习画像」。研究类功能（候选对比、双分支深算、热力图、棋力评估）全部保留，但不允许出现在学习动线的必经之路上。
2. **一个动作一个入口**：同一件事（如"判一次作答"）无论从哪里触发（字母按钮 / 棋盘自由落子），看到的判定逻辑与文案必须完全一致。
3. **数据诚实**：UI 上的每个数字都要能回答"它从哪来"。事实（KataGo 数值）、强推断（分支/意图）、建议（教练层）在文案上明确分层；证据不足时显示"待分类 / 数据不足"，绝不编。
4. **克制**：宁缺毋滥。没有证据支撑的标签（棋力档、棋风人格）要么改名（"一选冷门度"、"易执行候选"），要么降级为实验功能。

## 二、设计令牌（Design Tokens）

所有界面只允许引用令牌，禁止散落硬编码色值/字号/间距。

### 2.1 色彩（令牌唯一来源已迁至 `ui/tokens.py::PALETTE`，app.py 从其导入）

V6 新增：`learning_priority #9B8AFB`（只用于学习价值：时间轴外圈/重点标记/训练主题标题，绝不与白方指标混用——白方用 `white_metric`）；表面阶 `surface0-3`（#181D1E→#343D3E，Shell 底用 surface0）。

### 2.1-旧 色彩明细（值见 ui/tokens.py，语义如下）

统一明亮版深色（对标 OGS/KaTrain 深色模式），区域亮度等差递进（bg 0.150 → card 0.192 → card2 0.234），棋盘为明亮 kaya 榧木色。

| 令牌 | 值 | 用途 |
|---|---|---|
| `bg` | `#222829` | 窗口底色 |
| `card` | `#2c3334` | 卡片/表面底 |
| `card2` | `#363e3f` | 次级卡片、HUD 底 |
| `board` / `board2` | `#d4a85a` / `#e0b870` | 棋盘底色 / 木纹浅档 |
| `grid` / `star` / `coord` | `#4a3618` / `#3a2810` / `#6b5630` | 网格 / 星位 / 坐标（暖褐系，明亮棋盘上锐利） |
| `text` / `subtext` | `#e8ecec` / `#a8b1ac` | 主文本 / 次文本 |
| `accent` | `#3db8a0` | 青绿强调：主按钮、选中态、AI 首选标记 |
| `accent_h` / `accent_s` / `accent_m` | `#54d4be` / `#2a4a44` / `#4d9182` | hover / 选中底 / 中强调 |
| `black` / `white` | `#1a1a1a` / `#f8f8f0` | 棋子（白子微暖，云子质感） |
| `stone_hl_*` | 4 项 | 棋子高光/球阴影（PIL 预渲染） |
| `red` / `red_s` | `#e06560` / `#4a2e2c` | 恶手、危险、到期复习 |
| `amber` / `amber_s` | `#e0a043` / `#4a3a25` | 疑问、警告、可疑判定 |
| `green` | `#5abb80` | 好手、成功、判定通过 |
| `purple` | `#aa8ed8` | 白方相关、特殊标注 |
| `muted` | `#454f4a` | 边框/分隔线 |
| `shadow` | `#15191a` | 投影 |

语义规则：**红色只用于"确实有问题"**（恶手行、判定失败、到期未清）；amber 只用于"值得注意但不致命"；green 只用于判定通过与成功状态。禁止用红色做装饰。

### 2.2 字体阶梯（`FONTS`）

跨平台 fallback 链：UI 字体「微软雅黑 → Segoe UI → 苹方 → Noto Sans CJK」；数据字体「Consolas → JetBrains Mono → …」。

| 键 | 规格 | 用途 |
|---|---|---|
| `h1` | 16 bold | 窗口大标题 |
| `title` | 14 bold | 子窗口标题 |
| `score` | 20 bold | 胜率/目差数字（视觉焦点） |
| `section` | 11 bold | 卡片小标题 |
| `ui` | 10 | 正文 |
| `data` | 11 等宽 | 数值列（对齐） |
| `small` | 9 | 次文本、说明 |
| `micro` | 8 | 棋盘上的候选字母等微标注 |

### 2.3 间距（`SPACE`，4px 基准网格）

`xs=2, sm=4, md=8, lg=12, xl=16`。新代码禁止出现 3/6/9/14 之类凭手感值。

### 2.4 尺寸常量

- `RIGHT_PANEL_WIDTH = 396`：右边栏固定宽（主窗重构：原 480 收窄让宽给棋盘），棋盘区随窗口伸缩。
- 子窗口经 `_prepare_child_window(win, title, w, h, minsize=…, resizable=…)` 统一标题/层级/居中。

## 五、组件规范

### 5.1 按钮（`_make_button`，CTk 可用时圆角）

| 变体 | 外观 | 用途（每屏限量） |
|---|---|---|
| `accent` | accent 填充 + 白字 | 当前动线的主操作，每区域 ≤2 个 |
| `default` | card 底 + accent 描边 | 次操作 |
| `topbar` | 无底/细分隔 | 顶栏导航类 |

### 5.2 卡片

`_make_card_frame`：card 底 + muted 1px 边 + 标题（section 字号，accent 色）+ 内容区。卡片间距 `SPACE.lg`；卡片内边距 12。

### 5.3 表格（Treeview）行状态色

问题手表：`bad` 行 = red 前景 + red_s 底；`inaccuracy` = amber 系；`unknown` = subtext。列规格：手数/方/实战/AI参考评价/目损/胜率损失/AI建议/**学习类别**/标签。学习类别来自 taxonomy 九类，证据不足显示「待分类」。

### 5.4 数字与判定文案

- 数值一律等宽字体 `data`；目损保留 1 位小数；胜率百分号文案。
- 判定标签固定五档：`AI最佳 / 优秀 / 合理 / 可疑 / 明显问题`；数据不足显示「数据不足」。
- 主动复盘揭示固定三行对比结构：`你的实战 X：损失 a 目 ｜ 你的重选 Y：损失 b 目（判定 ✓）｜ AI 首选 Z：损失 0 目`，随后一行四分类结论。

### 5.5-新 候选区 v2（用户需求驱动）

- **3 个大按钮**（`big` 样式）：`序号(红) + 坐标`，右侧等宽字体只显示**胜率百分比**；徽章/推荐理由/PV 文字说明已移除。
- **单击即落子**（普通模式）；主变模式开启时点选=切换查看该选变化图（研究路径保留，用选中描边表达）。
- **棋盘候选标记**：红色数字 = 第几选择（与右栏序号一致，选中态用更大圆环区分，数字恒为红色令牌 `red`）。
- 配置默认 `candidate_count=3`；渲染循环有按钮数护栏，设置改大也不越界。

### 5.5 空态与提示

- 每个数据区必须有明确空态文案（如「尚未生成精细评价；完成整局分析后显示画像摘要。」），禁止留白或假数据。
- 引擎未就绪的降级路径都要给动作指引（如「请先对整盘做分析（复盘 → 补全分析）」）。

## 七、学习流交互规范（核心闭环）

1. **学习中心 = 学习模式首页**（大纲 §55-56 落地）：四入口按使用频率排列，「今日复习」有待办时按钮升 accent 且卡角标显示题数。
2. **本盘复盘 = 主动复盘**：quiz 态隐藏一切 AI 信息，棋盘可直接自由落子；榜外选点自动 allowMoves 强制分析；揭示后才显示候选表与变化图。判定/记账与字母入口完全同源（CandidateAssessment）。
3. **今日复习**：按实际目损判分；复习结果实时回写学习曲线与掌握状态。
4. **我的学习**：消费 LearningEvent 聚合指标；unstable 条目用 ⚠ 红字提示「复习会但实战仍复发」。

## 八、可信度展示规范（三级）

| 级别 | 来源 | UI 呈现要求 |
|---|---|---|
| 事实 | KataGo 数值 | 直接给数（等宽字体），可复核处附「可在变化图逐手核对」 |
| 强推断 | 分支对比/意图/复发统计 | 用「可能/据对比」措辞；置信度随附（高/中/低） |
| 建议 | 教练层/训练主题 | 用祈使句给出可迁移原则；无证据时宁可不显示 |

命名红线：不把启发式叫「棋力档」（→ 一选冷门度）；不把引擎 prior 叫人类概率（→ 易执行候选 = 小目损+短主变+清晰信号）；聚类根因叫「可能的根源」。

## 九、可访问性与可用性

- 快捷键：←/→ 撤回/前进；Space 自动播放；Ctrl+Z 悔棋；Ctrl+P 停一手；Ctrl+T 主题；Ctrl+O 导入；Ctrl+S 保存。
- 点目模式与训练作答阶段拦截会破坏状态的操作（进度条、Pass），并给出原因文案。
- 文本对比度：text/subtext 在 card 上 ≥4.5:1；红/amber 仅作状态色不作正文色。
- 所有子窗口 `transient` 主窗，关闭协议统一清引用（防僵尸窗口与状态残留）。

---

## 十、性能规范

- 棋盘底图、棋子、候选标记：PIL 3x 超采样 + Lanczos 预渲染，按参数缓存（`_stone_image_cache`），无 PIL 时降级 Tk 原生绘制。
- `redraw()` 节流合并；hover 只做增量层更新（`hover-stone` tag 删除重画），禁止鼠标路径整盘重绘。
- 批量分析结果经统一队列回流刷新，禁止逐条整窗刷新。

---

## 十一、测试钩子约定

UI 可测性是设计约束：PIL 化后无法从 canvas 断言的视觉序列，落成可读属性（如主变黑白底序列 → `_pv_marker_fills`）。新增视觉行为时同步提供同类钩子，冒烟测试按列名（非位置）读取表格值。
