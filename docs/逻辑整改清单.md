# 逻辑整改清单（v1）

> 触发背景：终局点目进入后落子/导航全被拦截，棋盘像被"锁住"——这是"形式判断阻挡棋盘"的典型。
> 根因不是单点 bug，而是**模式互斥/状态机不收口**：多个模式（点目、训练、quiz、错题复习、自动播放、分析队列）
> 各用散落的布尔标志表示，切换靠各入口手写守卫，覆盖不完整。
>
> 本轮按"模式互斥 / 单位一致性 / 降级完整性 / 硬编码魔数 / 文案一致性 / 死代码 / 反馈一致性"七类排查，
> 已修复 10 项（含用户痛点），列出待观察项。
>
> 审查与执行可复用：见文末「整改 subagent 使用说明」。

## 已修复问题（10 项，按严重度）

### 高优先级（逻辑错误 / 单位 / 死代码）

#### 1. [高·误判澄清] 棋风成本 `blunder_rate`/`inaccuracy_rate` 单位加注释
- **位置**：`style_cost.py:46-54`（消费）、`style_profile.py:260-263`（产出）、`style_report.py:72`（展示 ×100）
- **问题**：初读易误判为"单位错误"——产出端是 0-1 比例（`count/sample_count`），消费端阈值 `>=0.15` 看似当百分比用。
  **复查后确认语义正确**：0.15 作为比例就是 15%，`style_report.py:72` 的 `*100.0` 反证产出是比例，`test_style_cost.py:18` 用 `blunder=0.2`(20%) 触发 high 也自洽。
- **修复**：给 `cost_level` 加单位约定注释，防止后人误读误改。**未改逻辑**。
- **验证**：`test_style_cost.py`、`test_style_profile.py` 通过。

#### 2. [高·文案笔误] review.py "官子"误写"关子"
- **位置**：`review.py:26`（`PHASE_LABELS`）+ 文档串 4 处
- **问题**：`PHASE_LABELS = {..., "endgame": "关子"}`，而 `player_profile.py:35` 写的是"官子"，同项目内不一致，所有 review 展示文案都显示错字。
- **修复**：主标签统一为"官子"；`PHASE_ALIASES` 保留"关子"作容错别名（兼容已有用户数据/报告），加注释说明。同步更新 `test_review.py`、`test_review_report.py` 中对应的值断言。
- **验证**：`test_review.py`、`test_review_report.py` 通过。

#### 3. [高·死代码] training_analysis.py 三元两分支同值
- **位置**：`training_analysis.py:418`
- **问题**：`return "neutral" if not train_problem else "neutral"` 两分支完全相同，等价于 `return "neutral"`，是重构残留。
- **修复**：去掉误导性三元，改为直接 `return "neutral"`，并把注释补全——确认原意是"对齐不到原实战时不标 new_error"（`new_error` 仅在 `MATCH_EXACT_POSITION/MATCH_SAME_STEP` 下文判断，测试 `test:380-381` 验证）。
- **验证**：`test_training_analysis.py` 通过。

### 中优先级（模式互斥 / 状态机，含用户痛点）

#### 4. [中·用户痛点] 点目模式锁住棋盘
- **位置**：`app.py:1716`（`_block_in_scoring`）、`app.py:1737`（`_block_jump`）、`app.py:3267`（`enter_scoring` 状态栏）、`app.py:356`（Esc 绑定）
- **问题**：进入点目后 `play/undo/redo/pass/goto/step/import` 全被 `_block_in_scoring` 拦截，提示"请先【退出点目】"——但实际是再按【点目】按钮退出（toggle），文案与操作不对应；且无快捷退出，体感"被锁住"。
- **修复**（不改点目核心语义，改反馈和便捷退出）：
  - a) 拦截提示统一为"点目模式下不能 X，**按【点目】或 Esc 退出**后可继续操作"
  - b) 点目状态栏文案改为"● 点目模式（按 Esc 或【点目】退出）"
  - c) 新增 `_on_escape()`：点目激活时 Esc 退出点目，否则退出全屏（保留原全屏行为）
- **验证**：`test_ui_design.py`、`test_ui_product.py`、`app.py` py_compile 通过。

#### 5. [中·互斥缺口] 错题复习与训练/quiz 不互斥
- **位置**：`app.py:7085`（`_start_selected_mistake_review`）
- **问题**：进入错题复习只挡 `scoring_mode`，不挡 `_drill_active()` / `_training.active`，两个状态机可同时 active，落子行为冲突。
- **修复**：入口补齐 drill 和 training 守卫，与 `enter_scoring`/`open_problem_drill` 对齐。
- **验证**：`test_mistake_book.py` 通过。

#### 6. [中·导航漏拦截] 错题复习中导航键可漂离题面
- **位置**：`do_goto_root` / `do_goto_mainline_end` / `do_step` / `do_redo`
- **问题**：错题复习 active 时按 Home/End/PageDown/Right 可漂离题面节点，但 `_mistake_review` 仍 active，下次落子被 `_mistake_review_after_user_move` 强制拽回，状态错乱。
- **修复**：四个导航函数开头补 `_mistake_review.active` 检查（与 `_drill_active()` 检查并列）。
- **验证**：`test_mistake_book.py` 通过。

#### 7. [中·反馈缺失] `_on_click` drill 模式静默吞事件
- **位置**：`app.py:1527`
- **问题**：drill 模式点击棋盘直接 `return`，无任何提示，用户以为程序卡死。对比 `do_pass`(app.py:1700) 有 `_set_msg`，不一致。

## 整改 subagent 使用说明

本轮审查使用的可复用 agent 定义在 `~/.zcode/agents/code-auditor.md`。

**怎么调用**：在 ZCode 里用 Agent 工具，`subagent_type: code-auditor`，给它一个审查任务，例如：
- "审查 app.py 里所有模式标志的互斥性，找出半开半合的状态路径"
- "审查 style 模块各维度计算的单位和归一化是否一致"
- "复查本次整改后是否引入新的状态机漏洞"

**它的职责边界**：
- 七类排查清单：模式互斥/状态机、单位/类型一致性、降级完整性、硬编码魔数、文案一致性、死代码、反馈一致性
- 每条发现必须给 `file:line` + 代码摘录 + 严重度 + 修复建议
- 默认全部直接改并自测（已授权），改完跑对应 `test_*.py`
- 不重构巨型文件、不假装接入未实现模型、最小改动原则

**适合的后续场景**：
- 新增功能后做一次状态机互斥复查
- 定期跑一遍，找出积累的"逻辑不顺"
- 改动 app.py 大段代码前的体检

# 增量 v2：功能触发流程整改

> 触发背景：遍历每个功能的"进入→操作→退出→恢复界面"完整闭环，对标 KaTrain/LizzieYzy/星阵的触发编排，
> 修复"退出不彻底恢复 / 中途打断状态残留 / 入口拦截不全 / 弹窗连锁"等触发问题。
>
> **头号发现**：上一轮为加 Esc 退出点目而新增的 `_on_escape` 方法，误把 `__init__` 尾部的初始化代码
> （F1/Ctrl-*/WM_DELETE/poll_loop/autostart 等）裹进了函数体，导致应用首次按 Esc 前所有快捷键、
> 引擎自启、轮询、关闭保存全部不工作，每按一次 Esc 还会重复挂 poll_loop。这是上一轮引入的回归，本轮首要修复。

## 对标要点（来自 KaTrain/LizzieYzy 源码调研）

| 原则 | KaTrain 做法 | 本项目对照 |
|---|---|---|
| 困难功能做成游戏树状态/覆盖层，而非独占模式 | 点目=`t`键覆盖层、死活题=游戏树新节点、教学对局=玩家子类型，均无"进入/退出"按钮 | 本项目用模式标志（scoring_mode/training/drill），靠守卫收口——已加固 |
| 分析数据挂节点不挂全局 | 分析存在 GameNode 上，切棋谱/中断自然续算 | 本项目 node.analysis 已是此模型 |
| 长任务后台化+可中断+进度文字 | Escape=Stop all analysis，状态栏 STATUS_ANALYZING | 本项目批量分析已是后台+进度消息 |
| 常驻功能用可折叠 dock，弹窗只用于一次性确认 | CollapsablePanel 做胜率图/统计 | 本项目曲线/画像用独立 Toplevel（非模态），可接受 |

## 已修复的触发问题（9 项）

### [高·回归] T-1 `_on_escape` 吞掉 `__init__` 初始化代码
- **位置**：`app.py:359-386`（原）→ 已移回 `__init__`
- **问题**：上一轮新增 `_on_escape` 时，误把 `__init__` 尾部的 F1/Ctrl-z/Ctrl-p/Ctrl-t/Ctrl-o/Ctrl-s/Ctrl-l/Ctrl-r 绑定、`<Configure>`、`WM_DELETE_WINDOW`、`_poll_loop` 启动、`scan_library_inbox`、`_maybe_autostart`、`_kick_analysis_queue` 全部留在了 `_on_escape` 函数体内。
- **后果**：首次按 Esc 前——F1提示/Ctrl-*快捷键/保存/关闭/引擎自启/分析轮询全不工作；每按一次 Esc 重复挂 poll_loop 导致多实例并发。
- **修复**：把这 21 行初始化代码移回 `__init__`（紧跟 Esc 绑定之后），`_on_escape` 只保留 Esc 处理逻辑。
- **验证**：实例化后 F1/Ctrl-S/Esc 绑定立即就位，无需 Esc 触发。

### [高] T-2 关闭错题本窗口不清 `_mistake_review`
- **位置**：`_close_mistake_book` app.py
- **问题**：复习中关闭错题本窗口，`_mistake_review.active` 残留，后续任意落子触发对失效题目的"回题面"，其 parent 节点可能已属切换后的旧棋局，导致跨树跳转或崩溃。
- **修复**：`_close_mistake_book` 关窗时若复习仍 active 则置空并提示"已关闭错题本，进行中的复习已终止"。

### [中高] T-3 `_start_selected_mistake_review` 不停 auto_play
- **位置**：`_start_selected_mistake_review` app.py
- **问题**：开始错题复习时若 auto_play 在跑，会与复习落子逻辑冲突。
- **修复**：守卫通过后、切棋盘前调 `_stop_auto_play()`。

### [中] T-4 `enter_scoring` 不停 auto_play
- **位置**：`enter_scoring` app.py
- **问题**：点目锁定当前局面估分，但 auto_play 的 `_auto_play_step` 仍 `tree.redo()` 推进棋盘（redo 不走 `_block_in_scoring`），与点目语义冲突。
- **修复**：进入点目时调 `_stop_auto_play()`。

### [中] T-5 训练中导航键绕过训练锁定
- **位置**：`do_redo`/`do_goto_root`/`do_goto_mainline_end`/`do_step`
- **问题**：这四个导航键只拦截 drill/mistake_review，不拦截 training，导致训练中按 Right/Home/End/PageUp 可绕过训练锁定导航主线，使 `tree.current` 与训练 `nodes` 列表脱节。
- **修复**：四个函数在 mistake_review 检查后补 training 检查（与 `_block_jump` 一致）。

### [中] T-6 `_block_jump` 不拦 mistake_review
- **位置**：`_block_jump` app.py
- **问题**：复习中点击曲线/热力条/棋力条可跳转（它们走 `_block_jump`），绕过复习锁定。
- **修复**：`_block_jump` 补 mistake_review 分支，统一拦截四种模式（scoring/drill/training/mistake_review）。

### [中] T-7 切棋谱/reset/导入漏清训练缓存
- **位置**：`do_reset`/`_load_project_from_path`/`do_import_sgf`
- **问题**：只 `_training=None`，不清 `_training_prefetch_*`/`_training_deferred_nodes`/`_active_training_cache`，新树 nid 从 0 开始可能 stale 误命中。
- **修复**：新增 `_abandon_training_state()` 辅助方法统一清理（置空训练 + 清预取 + 清挂起节点 + 清活跃缓存），三处调用。

### [中] T-8 点目模式按"上一步"静默退出点目
- **位置**：`do_takeback`
- **问题**：点目下按"上一步"会静默退出点目并悔棋，用户不知道点目被关了。
- **修复**：记录 `was_scoring`，悔棋成功后明确提示"已退出点目模式并悔棋"；已在起点时提示"已退出点目模式（已在起点，无法悔棋）"。

### [低] T-9 `_close_problem_drill` 不刷新复盘面板
- **位置**：`_close_problem_drill`
- **问题**：关闭 drill 窗口只 `redraw`，不调 `_after_navigate`，复盘面板（曲线/失误榜/候选）不刷新到当前节点。
- **修复**：改为 `_after_navigate()`（内含 redraw）。

# 增量 v3：严厉触发流程审查（trigger-flow-auditor）

> 触发背景：用户反馈"打开棋谱库的棋谱还要自己退出""形式判断一直占据棋盘"——这些是用户一眼看出的体验缺陷，
> 但前两轮的 code-auditor 没抓到（它只查代码层正确性，不查交互层合理性）。
> 根因是 `_load_project_from_path` 打开新棋谱时不调 `exit_scoring()`，点目模式残留锁住棋盘 + 地盘图叠加层残留。
>
> 本轮新建了专门的 **trigger-flow-auditor** agent（严厉的触发流程审查员），从用户操作路径倒推、对照 KaTrain/LizzieYzy 基准，
> 找出并修复了 6 个触发缺陷（含用户反馈的 2 个）。

## 新增可复用 agent：trigger-flow-auditor

`~/.zcode/agents/trigger-flow-auditor.md` —— 专门审查"进入/操作/退出/恢复"闭环、模式间状态残留、打开新棋谱时的自动重置、叠加层遮挡。与 code-auditor（代码层）、product-analyst（产品层）形成三层互补，专攻**交互层合理性**这个前两者的盲区。

## 已修复的触发缺陷（6 项）

### [致命] T-10 打开棋谱库棋谱后点目模式残留，棋盘被锁（用户反馈）
- **位置**：`_load_project_from_path` app.py:2089（原不调 exit_scoring）
- **用户场景**：点目中双击棋谱库棋谱 → 新棋盘被 `_block_in_scoring` 锁住，点目地盘图叠在新棋盘上，必须手动 Esc 退出。
- **修复**：`_load_project_from_path` 开头加 `if self.scoring_mode: self.exit_scoring()`（对非点目态 no-op，安全）。

### [高] T-11 `do_import_sgf` 导入新棋谱不停自动播放（审查发现）
- **位置**：`do_import_sgf` app.py:2140（原缺 `_stop_auto_play`）
- **用户场景**：自动播放中导入新棋谱 → 新棋盘自己往前跳，▶ 按钮还显示"暂停"。
- **修复**：解析成功后、赋值新树前加 `_stop_auto_play()` + `if self.scoring_mode: self.exit_scoring()`。

### [高] T-12 三个换棋谱入口对点目模式行为不一致（审查发现）
- **位置**：`do_open_project`:2078（死守卫）、`do_import_sgf`:2140（拦截守卫）、`_open_selected_library_record`（无守卫自动退出）
- **用户场景**：同样换棋谱，Ctrl+O 和导入被点目拦住要先手动退出，棋谱库双击却能直接打开，行为不一致。
- **修复**：删除 `do_open_project` 和 `do_import_sgf` 的 `_block_in_scoring` 拦截守卫，统一为"换棋谱自动退出点目"范式（与 `_load_project_from_path` 对齐）。

### [中] T-13 训练报告双击跳转无 `_block_jump` 守卫（审查发现）
- **位置**：`_on_training_report_double_click` app.py:4822
- **用户场景**：点目模式双击训练报告某手 → 棋盘跳到该手，但 score_estimator 还建在原节点，点目地盘图错位叠加。
- **修复**：跳转前加 `if self._block_jump("跳转"): return`（与所有其它子窗口跳转一致）。

### [中] T-14 画像/棋风窗口打开新棋谱后不刷新（审查发现）
- **位置**：`_apply_analysis_result` 批量完成分支 app.py:3651
- **用户场景**：开着画像窗口，分析完一盘新棋 → 画像显示旧聚合数据，用户困惑。
- **修复**：批量分析完成时，若画像/棋风窗口开着则重开重算（`open_player_profile`/`open_style_profile` 本身是重开重算语义）。

### [已修复确认] T-15 形式判断 HUD vs 点目地盘图（用户反馈，诊断澄清）
- **诊断**：用户说的"形式判断一直占据棋盘"实际是**点目地盘图**（`_draw_scoring_overlay`）在 scoring_mode 残留时持续画——和 T-10 是同一根因。形式判断 HUD（右上角小卡片）本身是合法的常驻设计，可关闭、不挡棋子、不锁交互。T-10 修复后地盘图残留问题一并解决。

## 审查方法论（trigger-flow-auditor 的三个零容忍）

1. **"打开新东西后，旧状态还赖着"** —— 切换全局上下文（打开棋谱/导入/重置）必须自动重置所有临时状态。
2. **"进入某状态后出不来 / 出来后界面没恢复"** —— 每个进入都有清晰可见的退出，退出后界面完整恢复。
3. **"叠加层一直占着棋盘，该让位时不让"** —— 覆盖层在模式切换/棋谱切换时自动隐藏或刷新。

本轮已确认所有叠加层（scoring/situation/heat/drill/candidate/problem_branch/hint）在 redraw 里的条件分支正确，仅 scoring 因 scoring_mode 残留而异常（已修）。
