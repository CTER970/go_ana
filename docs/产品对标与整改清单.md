> 判断本项目（个人本地围棋分析器，单机复盘教练定位）哪些功能"待完善"、哪些"冗余用处不大"。
>

> 这是本地工具相对在线平台唯一能形成壁垒的方向（在线平台有数据但多为单局复盘，本地工具反而能深度聚合个人所有棋谱）。

## 已完成的整改（本轮）

### 待完善项（GAP）—— 已实现 2 项

#### GAP-1 [高] 整盘问题手热力概览色带
- **现状（改前）**：曲线窗口（`toggle_graph`）只有"胜率曲线+柱状图"，柱状图按手数轴画目损柱，但形态是竖线柱，不够"一眼概览"。
- **对标**：LizzieYzy Next 底部"整盘问题手热力条"——细长连续色带，红橙黄一眼定位最该看的手。
- **修复**：在曲线窗口的曲线与柱状图之间，新增一条 20px 高的热力概览色带（`_refresh_heat_bar`）：
  - 每个问题手（loss≥GRADE_GOOD）在对应手数位置画色块，按严重度着色（恶手红/疑问橙/轻微蓝）
  - 当前进度竖线指示（与曲线、柱状图同步）
  - 点击色带可跳转到对应手（`_on_heat_click`，复用跳转守卫）
  - 数据源完全复用现有 `rr.evaluate()`，与曲线共用 `max_move` 手数轴，三者竖向对齐
- **位置**：`app.py` `_refresh_heat_bar`、`_on_heat_click`、`toggle_graph`（窗口布局）、`_refresh_graph`（调用）、`_close_graph`（清理）、`__init__`（状态初始化）
- **验证**：`test_ui_design.py`、`test_ui_product.py`、`app.py` py_compile 通过

#### GAP-2 [高] 快速预扫（低 visits 全盘补曲线）
- **现状（改前）**："分析整盘"只用配置的 `maxVisits`（默认200）一次性跑完，200手的棋要等较久才能看到问题手分布。
- **对标**：LizzieYzy 用 38MB 轻量模型快速跑完全盘补胜率曲线，不抢主引擎。
- **修复**：给"分析整盘"按钮旁加"快速预扫"按钮（`quick_scan_mainline`）：
  - 用低 visits（80，与训练 fast 档一致）快速跑完整盘，先定位问题手分布与胜率曲线
  - `_request_analysis` 已支持 `visits` 参数，改动集中在 `analyze_mainline(quick=True)` 传 `quick_visits`
  - 预扫完成后，问题手仍可用"分析当前局面"或双分支对比深算（已有功能）
  - **不起双进程、不自动触发高visits深算**（避免重复消耗算力、与 branch_comparison 撞车）——这是用单引擎 visits 分档实现的轻量方案
  - 默认行为零变更（点"分析整盘"仍是标准200v）
- **位置**：`app.py` `analyze_mainline(quick=)`、`quick_scan_mainline`、`_build_card_analysis`（按钮）、`columnconfigure`
- **验证**：`test_ui_design.py`、`test_ui_product.py`、`test_analysis_product.py` 通过

## 产品分析 agent 使用说明

本轮使用的可复用 agent 定义在 `~/.zcode/agents/product-analyst.md`。

**怎么调用**：在 ZCode 里用 Agent 工具，`subagent_type: product-analyst`，给它任务，例如：
- "重新评估当前功能集，找出新的待完善/冗余项"
- "评估是否应该加入定式训练功能"
- "对比最新版 LizzieYzy，看我们落后了什么"

**它的职责边界**：
- 联网对标主流工具（涨棋网/星阵/KaTrain/LizzieYzy/Sabaki/野狐）
- 三类分类：待完善(GAP，行业公约数或定位核心但缺失)、冗余(REDUNDANT，超出定位或零价值残留)、亮点(STRENGTH，应继续强化)
- 判断标准：单机复盘教练定位（复盘+训练+画像做深，砍对弈/联网）
- **判冗余极其谨慎**：宁可保留也不误删，只动明确超出定位或零价值残留
- 默认直接实现/清理并自测

**适合的后续场景**：
- 每次大版本更新后做一次产品体检
- 评估新功能提议是否符合定位
- 定期对标市面最新动态
